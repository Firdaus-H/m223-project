# Game Library - database-backed Quarkus starter

Package: `dev.gamelibrary`

This is a **source-file overlay** for your existing empty Quarkus project. It does not replace your project's `pom.xml` or Maven wrapper.

## Extensions

From your project root:

```bash
./mvnw quarkus:add-extension -Dextensions="rest-jackson,hibernate-orm-panache,jdbc-h2,elytron-security-common,smallrye-openapi"
```

H2 is an **embedded SQL database** (no Docker). Its data is saved in `./gamelibrary.mv.db` relative to the working directory. Add `gamelibrary*.db` to `.gitignore`.

Copy `src/main/java/dev/gamelibrary` and `src/main/resources/application.properties` into your project. If you already have settings in application.properties, merge the settings instead of overwriting them.

Start: `./mvnw quarkus:dev`  — Swagger UI: `http://localhost:8080/q/swagger-ui`

In dev mode, the first startup creates a demo user (`demo` / `demo`), two genres and two games. Demo user password is bcrypt-hashed; **change or remove the test account before any deployment**. Restarting the application does not erase the database. IDs are **generated by the database**: do not provide `id` on POST.

## Endpoints

- `POST /auth/register` — `{ "username": "newuser", "password": "secret" }`
- `POST /auth/login` — same shape; **returns a user profile only**, not a JWT (demo login)
- `GET /games`, `GET /games/{id}`, `POST /games`, `PUT /games/{id}`, `DELETE /games/{id}`
- `GET /genres`, `POST /genres`, `PUT /genres/{id}`, `DELETE /genres/{id}`
- `GET /library?userId=1`, `POST /library`, `PUT /library/{id}`, `DELETE /library/{id}`

POST /games sample:

```json
{"title":"Stardew Valley","description":"Farming game","releaseDate":"2016-02-26","genreId":1}
```

POST /genres sample:

```json
{"name":"Strategy"}
```

POST /library sample:

```json
{"userId":1,"gameId":1,"status":"PLAYING","rating":8}
```

PUT /library/{id} sample (only status and rating change):

```json
{"status":"COMPLETED","rating":9}
```

## Database relationships

- `ApplicationUser` 1:N `LibraryEntry`
- `Game` 1:N `LibraryEntry`
- `Genre` 1:N `Game`

The Java entity classes use `@Entity`, `@Id`, `@GeneratedValue`, `@ManyToOne` and `@JoinColumn` like Punchclock. `GameDto` and `LibraryEntryDto` expose foreign-key IDs in JSON without exposing JPA entity graphs.

## Deliberate limits for this assignment

- Registration/login are **not authentication or authorization**: library userId comes from the request and is not protected. Do not deploy this publicly as a personal-library system. Real JWT protection can be added later.
- Status is a simple string (`PLAYING`, `COMPLETED`, etc.); rating must be 1–10 when provided.
- Deleting a genre with games, or a game still referenced by library entries, returns 400 until related records are removed.
- Dev schema `update` is for local coursework, not production migrations.
- No playtime attribute anywhere.
